Machine Learning-Based Phishing Website Detection

IS41070 — Machine Learning Foundations · MSc Information Systems, UCD · PhiUSIIL Phishing URL Dataset (UCI ML Repository)
DATASET SIZE
235,370URLs
MODELS COMPARED
6+ baseline
FINAL TEST F1
99.98%
TEST ERRORS
5/ 35,306

A supervised binary classifier that distinguishes phishing websites from legitimate ones using 50 engineered URL and webpage features — transport protocol, domain structure, character composition, and content signals. Phishing was set as the positive class so precision, recall and F1 map directly onto a security-relevant question: how many malicious sites slip through, and how many legitimate sites get wrongly blocked?

The pipeline was built with leakage prevention as a first-class concern: duplicate URLs were removed before the stratified 70/15/15 split, and the held-out test set was touched exactly once, after the final model and hyperparameters were already locked in.

  1. EDA on 235,795 raw observations — class balance, skew, multicollinearity, high-cardinality fields
  2. Leakage-safe cleaning & stratified train / validation / test split
  3. Six classifiers trained: Logistic Regression, Decision Tree, Random Forest, Linear SVM, Gaussian Naïve Bayes, Histogram Gradient Boosting
  4. Dominant-feature ablation — removed 3 suspiciously strong predictors to pressure-test whether "near-perfect" results were genuine
  5. Focused hyperparameter tuning, then 5-fold stratified cross-validation on the top finalists
  6. One-time held-out test evaluation, followed by permutation-importance interpretation
Why this matters for security work

Several models scored a perfect F1 of 1.000 on first pass — a result treated as a warning sign, not a win. An ablation test removing the three most dominant features exposed that Gaussian Naïve Bayes had been leaning almost entirely on them (F1 fell from 0.999 to 0.915), while the boosting model barely moved.

That instinct — distrust results that look too clean, verify before trusting the alert — is the same posture SOC triage needs when a detection rule looks suspiciously perfect.

Final model — Histogram Gradient Boosting

On the untouched 35,306-row test set: 20,227 true negatives, 1 false positive, 4 false negatives, 15,074 true positives. Permutation importance ranked IsHTTPS, NoOfSubDomain and LineOfCode as the strongest retained signals. Limitations are reported directly: the split was row-level rather than domain-grouped, no chronological or external-dataset validation was performed, and the 4 false negatives are treated as a real risk, not a rounding error.
